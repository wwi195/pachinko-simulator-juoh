## 2. 遊技条件

- 交換レート: 等価（4円/球）
- 回転数レート: 選択式 `[22, 25, 26.3, 28, 31]`、デフォルト `26.3`（等価ボーダー付近）。1回転コスト = 250 / レート（球）
- 軍資金上限: 無し
- 回転数上限: 累計2000回転で「営業時間終了」アラート（居座る／退店）。rezero2と同じ挙動

## 4. RUSH/LT構造タイプ: ⑧ ST＋チャージ型LT（新規）

### 4-1. 初当たり → 獣王RUSHチャレンジ
- 初当たりは全部2R・表示300発／実質280発
- 「チャレンジ」ボタンで判定。`P_RUSH_ENTRY = 0.5` で獣王RUSH突入、失敗で通常時へ戻る

### 4-2. 獣王RUSH
- ST100回転、`P_RUSH = 1/144.7`（継続率 = 1 − (1 − 1/144.7)^100 ≒ 49.98%）
- 当選したら「チャージ！」に移る。チャージ終了後はSTを100にリセットして獣王RUSHを継続する
- 100回転すべて外れたらRUSH終了 → RUSH結果画面 → 通常時

### 4-3. チャージ（RUSH中の当たり1回の中身）

パラメータ:

| 項目 | 値 |
|---|---|
| 当該抽選・保留1個の当選確率 `P_CHARGE` | 1/4.13 |
| 再チャージ率 `P_RECHARGE` | 0.62 |
| 1回の当たりの出玉 | 表示1500／実質1400 |
| 保留の上限 | 4 |

流れ:
1. **当該抽選（初回）**: 1/4.13を当たるまで回し、何回転目で当たったかを記録する。＋1500。初回の当該では再チャージ判定をしない
2. **保留チャージ**: 保留を4個まで補充する。補充した時点で各保留の中身（当たり/ハズレ、各1/4.13）を決めて表示する
3. **保留消化**（ボタン1回につき1個、前から順に）:
   - 当たり: ＋1500。持っている再チャージの権利を消費（false）したうえで、改めて62%で再チャージ判定
     - 成功: 権利をtrueにし、残りの保留はそのままで4個まで補充する
     - 失敗: 補充しない
   - ハズレ: 何もしない
4. **保留切れ**:
   - 権利あり: 権利を消費して**再チャージの当該抽選**（1/4.13を当たるまで回す、回転数を表示）。＋1500。この当たりでも62%の再チャージ判定（成功なら権利true）。その後、保留を4個補充して3に戻る
   - 権利なし: チャージ終了

結果の区分（合計表示出玉）:

| 合計 | 区分 |
|---|---|
| 1500 | 1500BONUS |
| 3000 | 3000BONUS |
| 4500以上 | サバンナチャンス |

検証値（仕様どおりの実装で100万回）: 1500 33.0%／3000 16.1%／SC 51.0%、SC平均9,861発、SC内訳 4500 22%／6000 17%／7500 13%／9000 10%／10500以上 37%、RUSH当たり1回平均 約6,000発。

### 4-4. logic.js のインターフェース（イミュータブル）

```js
createChargeState()        // { phase:'gai_initial', holds:[], recharge:false, hits:0, nominal:0, actual:0, lastGaiSpins:0, isInitialGai:true }
applyChargeStep(state)     // → { state, event }
```

`phase` と `applyChargeStep` の挙動:

| phase | 処理 | event |
|---|---|---|
| `gai_initial` | 当該を当たるまで回す（`rollUntilHit()`で回転数）、＋1500、保留を4個補充 → `holds` | `{ type:'gai', spins, recharge:null }` |
| `holds` | 先頭の保留を1個消化。当たりなら＋1500＋再チャージ判定（成功で補充）。消化後に保留が0なら、権利ありで `gai_recharge`、権利なしで `done` | `{ type:'hold', hit, rechargeResult: true/false/null, refilled }` |
| `gai_recharge` | 権利を消費し、当該を当たるまで回して＋1500、再チャージ判定、保留を4個補充 → `holds` | `{ type:'gai', spins, recharge: true/false }` |
| `done` | 何もしない | `null` |

補助関数:
- `rollUntilHit()` — 1/4.13の幾何分布で回転数（1以上）を返す
- `classifyCharge(nominal)` — `'b1500' | 'b3000' | 'savanna'`
- `fillHolds(holds)` — 4個になるまで `Math.random() < P_CHARGE` の中身で補充した新しい配列を返す

RUSH側:
- `createRushState()` / `applyRushSpin(rushState)` — rezero2と同じ形。当たり時の出玉はチャージ側で加算するので、`applyRushSpin` はST消化と当選判定だけ行う（`outcome: 'hit' | 'miss' | 'st_end'`）

### チャージ画面の表示
- 見出し「チャージ！」、累計出玉（表示発数）、当たり回数

## 8. テスト（node:test）

- 定数: `P_HIT`, `P_RUSH`, `RUSH_ST_COUNT=100`, `P_CHARGE`, `P_RECHARGE`, レート選択肢とデフォルト
- `calcSpinCost(26.3)` = 250/26.3
- `fillHolds` が4個に補充し、既存の保留を残す
- `applyChargeStep` の決定的テスト（`Math.random` をスタブ化）:
  - 保留全ハズレ → 1500で `done`
  - 保留1当たり・再チャージ失敗 → 3000
  - 再チャージ成功で残り保留を保持したまま4個に補充される
  - 権利ありで保留切れ → `gai_recharge` → 当該で＋1500、保留4個
  - 権利は次の当たりで消費され、再判定される
  - 初回の当該では再チャージ判定しない
- 統計テスト（20万回）: 振り分け 1500 33±1.5%、3000 16±1.5%、SC 51±1.5%、SC平均 9,860±300
- `applyRushSpin`: ミスでST減少、100回目のミスで `st_end`、当たりでST100にリセット・連チャン+1
